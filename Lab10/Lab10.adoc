== Операционная система реального времени (RTOS)

Операционная система реального времени (RTOS) - это операционная система, предназначенная для выполнения задач в условиях ограниченности ресурсов. RTOS используются в проектах, где важны точная временная синхронизация и быстрая реакция на события.

=== Планировщик

Как правило, микроконтроллеры имеют только одно ядро, которое может выполнять в конкретный момент времени только одну задачу. Например, при возникновении начинается его обработка, однако во время его обработки вся программа "зависает" до тех пор, пока обработка не будет завершена. Чтобы этого избежать, используют операционную систему реального времени. Она позволяет разбивать задачи так, чтобы они выполнялись по частям. Например, сначала выполняется часть задачи, потом ее выполнение прерывается и начинает выполняться другая, а потом выполнение первой задачи завершается.

Для того, чтобы управлять задачами, существует планировщик. Он распределяет между задачами процессорное время, определяя, какая задача будет выполняться в данный момент времени, когда между задачами следует переключаться и как обрабатывать их приоритеты и состояния.

В RTOS у задач существуют статусы задач:

* Running - выполняется;
* Ready - готова к выполнению;
* Blocked - заблокирована (ждет какого-то события, чтобы продолжить выполнение);
* Suspended - приостановлена (временно исключена из планирования вручную).

Стоит учитывать, что на самом деле задачи не выполняются одновременно, т.к. микроконтроллер имеет лишь одно ядро. Однако благодаря планировщику, распределение процессорного времени получается настолько эффективным, что кажется, будто задачи выполняются параллельно.

=== События (Events)

В операционных системах реального времени существуют события. События - это механизм синхронизации, который уведомляет задачи о наступлении определенных действий или изменений в системе.

В проекте имеется файл *event.hpp*, в котором реализовано событие:

.event.hpp
[source, cpp]
----
#ifndef EVENT_HPP
#define EVENT_HPP

// For tEvent
#include "rtosdefs.hpp" //for tTime
#include "rtoswrapper.hpp" //for RtosWrapper
#include "eventmode.hpp" // for EventMode


namespace OsWrapper
{

  constexpr tTime waitForEver = 0;
  constexpr tEventBits defaultMask = {0b11111111};

  class Event
  {
  public:
    __forceinline explicit Event(const std::chrono::milliseconds delay, const tEventBits maskBits) :
        timeOut{(std::chrono::duration_cast<TicksPerSecond>(delay)).count()},
        mask{maskBits}
    {
      handle = RtosWrapper::wCreateEvent(event);
    }

    __forceinline ~Event()
    {
      RtosWrapper::wDeleteEvent(handle);
    }

    __forceinline void Signal()
    {
      RtosWrapper::wSignalEvent(handle, mask);
    }

    __forceinline tEventBits Wait(const EventMode mode = EventMode::waitAnyBits,
                                  const tEventBits maskBits = defaultMask) const
    {
      return RtosWrapper::wWaitEvent(handle, maskBits, timeOut, mode);
    }

    __forceinline void SetTimeout(std::chrono::milliseconds delay)
    {     
      timeOut = (std::chrono::duration_cast<TicksPerSecond>(delay)).count();
    }

    __forceinline void SetMaskBits(tEventBits maskBits)
    {
      mask = maskBits;
    }

  private:
    tEventHandle handle{0};
    tEvent event;
    tTime timeOut = 1000;
    tEventBits mask{defaultMask};
  };
};

#endif // EVENT_HPP
----

Основной метод этого класса - метод *Signal()*. Он оповещает систему о том, что событие активировалось и требует обработки.

Метод *Wait()* ожидает наступления события, блокируя вызывающую задачу до выполнения условий, заданных параметрами.

=== MailBox

Главное отличие MailBox от событий заключается в том, что *MailBox* не только сигнализирует о необходимости обработки задачи, но и передает данные. Так, например, *MailBox* может передать конкретные данные: число, строку, адрес и т.д.

Реализуем те же самые задачи, используя MailBox. В проекте существует класс MailBox, реализованный в файле *mailbox.hpp*.

.mailbox.hpp
[source, cpp]
----
#ifndef MAILBOX_HPP
#define MAILBOX_HPP

#include "rtosdefs.hpp"
#include <array>  ///for std::array
#include <chrono> // for 'ms' literal
#include "rtoswrapper.hpp" // for RtosWrapper

namespace OsWrapper
{

  template<typename T, std::size_t size>
  class MailBox
  {
    public:
    __forceinline MailBox()
      {
        handle = RtosWrapper::wMailBoxCreate(size, sizeof(T), buffer.data(), context);
      }

    __forceinline ~MailBox()
      {
        RtosWrapper::wMailBoxDelete(handle);
      }

    __forceinline bool Put(const T &item)
      {
        return RtosWrapper::wMailBoxPut(handle, &item);
      }

    __forceinline bool Get(T &item, std::chrono::milliseconds timeOut)
      {
        return RtosWrapper::wMailBoxGet(handle, &item, std::chrono::duration_cast<TicksPerSecond>(timeOut).count());
      }

    private:
      tMailBoxHandle handle;
      tMailBoxContext context;
      std::array<std::uint8_t, size * sizeof(T)> buffer;
  };
}
#endif //MAILBOX_HPP
----

В классе MailBox существует только 2 метода: *Put()* - положить данные в буфер и *Get()* - извлечь данные.

=== Critical Section

При обработке задач в операционных системах реального времени может возникнуть следующая проблема. Если у задач назначен приоритет, и при этом несколько задач выполняется параллельно, то задача, имеющая более высокий приоритет, может вытеснить задачу, имеющую более низкий приоритет так, что последняя либо выполнится не до конца, а только ее часть, либо не выполнится вовсе.

Покажем на примере. Имеется 2 задачи, выводящие в терминал сообщения. У задачи *LedTask* приоритет выше, чем у задачи *ButtonTask*.

Как можно заметить, задача *LedTask* временами вытесняет задачу *ButtonTask*, прерывая ее выполнение.

Чтобы избежать такого развития событий, существует несколько методов. Один из них - использолвание критической секции (*Critical Section*).

Суть работы критической секции заключается в том, что при обработке требуемого ресурса она отключает все прерывания в микроконтроллере, чтобы другие задачи не смогли вмешаться в процесс выполняемой задачи.

В проекте критическая секция реализована в файле *criticalsection.hpp*

.criticalsection.hpp
[source, cpp]
----
#ifndef CRITICALSECTION_HPP
#define CRITICALSECTION_HPP

#include "rtoswrapper.hpp" // for RtosWrapper

namespace OsWrapper
{
  class CriticalSection
  {
    public:
      inline CriticalSection()
      {
        RtosWrapper::wEnterCriticalSection() ;
      } 
      
      inline ~CriticalSection()
      {
        RtosWrapper::wLeaveCriticalSection() ;
      } 
  } ;
} ;
#endif // CRITICALSECTION_HPP
----

В классе *CriticalSection* имеются только конструктор и деструктор. При инициализации объекта класса прерывания отключаются, а при его удалении включаются снова. Используем критическую секцию для устранения проблемы.

=== Mutex

У критической секции есть существенный недостаток: она блокирует все прерывания на достаточно большой промедуток времени. Если во время прерываний производились какие-то расчеты, то он могут не успеть завершиться.

Для того, чтобы работать только с задачей и не отключать все прерывания в целом, существует примитив, называемый *Mutex*. В проекте он реализован в файле *mutex.hpp*.

.mutex.hpp
[source, cpp]
----
#ifndef MUTEX_HPP
#define MUTEX_HPP

#include "FreeRtos/rtosdefs.hpp"
#include "rtoswrapper.hpp" //for RtosWrapper

namespace OsWrapper
{

  class Mutex
  {
    public:
      __forceinline Mutex(): handle(RtosWrapper::wCreateMutex(mutex))
      {
      }

    __forceinline ~Mutex()
      {
        RtosWrapper::wDeleteMutex(handle);
      }

    __forceinline bool Lock(tTime timeOut = (std::chrono::duration_cast<TicksPerSecond>(1000ms)).count())
      {
        return RtosWrapper::wLockMutex(handle, timeOut) ;
      }

    __forceinline void UnLock()
      {
        RtosWrapper::wUnLockMutex(handle);
      }

    private:
      tMutex mutex;
      tMutexHandle handle;
  };
}
#endif //MUTEX_HPP
----

У класса *Mutex* имеется 2 метода: *Lock* - заблокировать ресурс, *UnLock* - освободить ресурс.
